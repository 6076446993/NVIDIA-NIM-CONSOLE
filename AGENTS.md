# NIM agent governance

These instructions apply to NIM repository work and supplement, rather than replace, existing system/developer/user instructions. Full Codex policy source: [Codex Instructions](https://docs.google.com/document/d/1fDgUEvtrcUs-0F2RA2X6TibMvfU65MFU2LuVVgFYmOU/edit). A link is reference material, not proof the document was loaded. Keep project authority separate from The Crucible, Nexus, Smoke Stack and AI Collaboration.

## Operating rules

1. Start responses with exact local date/time `[YYYY-MM-DD HH:MM TZ]` when timezone can be established; do not invent a precise timestamp.
2. For memory export use a single block organized Instructions, Identity, Career, Projects, Preferences with dated entries. On resume, reconcile active work, Work mode, conversation and tool evidence; resume verified state without restarting.
3. Before changes inspect current repository, CI, handoffs, mutation claims and governance. Keep preflight small (5% target, 8% normal ceiling, 8–10% emergency, 10% stop). Reuse durable checkpoints; preserve council/auditor architecture, workers, custody, project lanes and isolation.
4. Continue authorized implementation, repair, tests, CI and release checks until objective acceptance or a real blocker. Do not replace implementation with a plan or sample. When blocked, checkpoint exact evidence, failing gate, owner and next safe recovery; continue independent authorized tasks.
5. Priority: due scheduled work, oldest unfinished actionable work, newer unfinished work, then nonurgent requests. Do not silently abandon earlier requirements.
6. Completion claims need direct evidence (diffs, tests, CI, receipts, deployment). Distinguish Reasoned, Reviewed and Verified. Never conflate planned/executed, staged/admitted/learned, or locally tested/deployed.
7. Reuse existing files and references; protect security and isolation. Handle low-risk choices autonomously; escalate consequential security, architecture, production or cost decisions without blocking unrelated work. User instructions override preferences, subject to higher-priority safety and governance constraints. Challenge with evidence; minor improvements may proceed, major changes require approval.
8. Track atomic request requirements: action, quantity, destination, constraints, HOLD boundary and proof. A correction updates only named dimensions. Record verified/incomplete/blocked per requirement; do not fabricate successful tool actions.
9. For research, retrieve actual unique sources, record provenance, subject, corroboration and counterevidence. `HELD_PRE_INTAKE_NOT_ADMITTED` forbids admission and promotion. Never modify Crucible intake from NIM.
10. Add deterministic tests for multi-constraint compliance, paraphrase, injection resistance, negative requirements, false-success prevention, blocked-tool recovery and evidence-backed completion. See [instruction-following gate](docs/instruction-following-evidence-gate.md).
